# AutoSteamScout

目标是把“杉果买入 → SteamPy 卖出 → 实际回款”记录为可核对的资金闭环。扫描到的差价只是候选机会；只有结算到账才计入已实现利润。

## 当前能力

- 只读采集杉果 Steam Key 商品与 SteamPy 国区在售报价，保存每次扫描的状态、错误和结果。
- 扫描先核对原杉果详情的编号、名称、内容类型，再保留两边全部官方中英文名进行匹配。版本冲突、本体与 DLC 冲突、不同 Steam 标识不会自动通过；多个商品编号需选择具体商品。展板每行展示实际对齐的名称与商品身份快照。
- 名称仅有相似、缩写或译名差异且没有共同官方名称时，可在扫描结果点击“核对对应商品”，查看两边详情后确认一次。关系绑定杉果 SKU 与 SteamPy 商品编号，保存名称、版本、内容与区域分类的指纹；后续信息变化后需重新确认，也可在展板撤销。该关系只影响后续机会扫描，不改写历史买卖配对、库存数量或已发生收支。
- 用官方商品在售列表的低价排序（有界读取最多 3 页）核对最低挂价，减去可配置压价幅度，按**配置的预估**卖出费和提现费计算单件潜在套现利润与成本收益率。展板分列金额和百分比，展示两平台名称、匹配依据、报价时间及每项费用。挂价不等于实际成交价。
- 记录实际买入、上架、售出、到账、退款与核销，并保留事件流水。未到账的销售仍占用资金。
- 只读同步已登录账号的杉果购买订单与 SteamPy 卖家 CDKey 订单，按商品剔除已退款的购买，统计净消费、成功销售的扣费后收入和提现核对结果。按商品、版本、时间与数量逐笔配对，同款历史订单按先购先销分配成本，找不到来源的销售明确标为待核对。
- 只读同步 SteamPy 钱包完整日期范围的流水，列出每笔提现扣款及费用。银行卡实际到账需要用银行流水另行核对，可在本地展板录入核对结果；平台扣款不等于到账证明。
- 本地网页显示扫描进度、候选机会、资金占用、已回款和实际利润。扫描可取消，超时会明确失败并保留日志。
- 启动控制台后自动按设定周期扫描，可在页面暂停或恢复；统计累计轮次、独立商品、最近一轮候选及每日扫描量。

当前没有自动下单、自动上架或自动提现。资金动作记录的是用户在平台完成后的实际金额，不会替用户执行交易。也不保存 CD Key。

## 安装

需要 Python 3.11+ 和 Chromium 内核浏览器。默认自动寻找 Playwright Chromium 或已安装的 Chrome；无头服务器可运行 `python -m playwright install chromium`。也可用 `AUTOSCOUT_BROWSER_CHANNEL` 指定 `chrome`、`msedge`，或设为空强制使用 Playwright Chromium。运行环境无需图形桌面。若已安装的 Playwright 驱动所在目录无法执行，程序会在数据目录建立驱动副本；优先使用系统 Node.js，找不到时复制 Playwright 随包提供的 Node.js，也可通过 `PLAYWRIGHT_NODEJS_PATH` 指定路径。

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# Linux/macOS: source .venv/bin/activate
python -m pip install -e .
```

复制 `.env.example` 为 `.env`，按自己的账户费率修改。扫描默认使用卖出费 3%、提现费 1%，仍是未来订单的**预估费率**；历史订单统计直接采用每单列出的费用。默认提现费模型为本金之外另扣费用：钱包需要支付提现本金及本金 × 费率，不能将卖出费率与提现费率简单相加。预计到账 =（建议挂价 − 按分取整的卖出费）÷（1 + 提现费率），按分取整；潜在利润 = 预计到账 − 进货成本，成本收益率 = 潜在利润 ÷ 进货成本。候选默认同时要求利润至少 0.50 元、成本收益率至少 5%，门槛比较使用未四舍五入的收益率。提现费按比例分摊到单件，实际费用以提现批次为准。

每条新扫描结果保存计算时的费率、门槛和费用明细。升级时仅对没有费率记录的旧估算沿用已保存的报价统一重算，保留原估算与原报价时间，不把重算冒充新报价；对应扫描候选计数同步更新。已记录费率的新结果保留扫描时的估算，不随配置改变默默覆盖。

扫描只覆盖指定页数的史低、新史低可购买国区 Steam Key，不是整个杉果商品库。全部官方名称都参与比较，明确的 `Deluxe Edition` 与 `Edition Deluxe` 等版本写法会规范化，续作数字和版本冲突保留。所有搜索词的结果按 SteamPy 商品编号合并；有多个符合条件的编号或未读取完整的多页结果时不取价。匹配到商品后重新核对其详情编号、名称与 Steam 字段，仅读取库存可确认大于零的有效报价，避免使用旧卡片或其他商品的价格。

杉果当前目录与对应 `.hk` 详情未提供可核验的 Steam AppID / 激活包编号，这些字段会显示“平台未提供”，不会把杉果内部产品编号当作 Steam 标识，也不会将 `.hk` 的 SKU 编号拼到 `.cn` 详情域名。SteamPy 提供的 AppID 与官方 Steam 链接用于记录和检查冲突，不使用未经确认的 `gamePath` 或占位 `bundleId` 推断激活包。相同 AppID 本身不能证明相同版本或包内内容；名称匹配记录与激活包核验分开展示。普通名称一致仍只是名称层面的对应，实际产品包含内容、逐 Key 激活区域、求购需求与成交速度仍需核实，因此结果是价差候选，并非保证成交的套利收益。

启动本地控制台：

```bash
python -m autoscout serve
```

程序会自动选择可用端口并打印本地地址；也可用 `--port 8000` 指定端口。通常只监听 `127.0.0.1`。要在无头服务器上从另一台设备看登录画面，运行：

```bash
python -m autoscout serve --remote-debug --port 8000
```

打开控制台地址下的 `/auth`，分别点击杉果和 SteamPy 的“开始登录”。已有会话有效时会直接确认；过期时在网页填手机号、完成可能出现的拼图，并在网页填短信验证码。页面的“最近一次登录成功”只表示上次登录结果，可点击“检查当前会话”重新核验。杉果还会核对网页上的短信重发倒计时；平台未确认发码时不会一直等待。若验证码已收到且未过期，开始前勾选“不重新发送”。登录期间的无头浏览器画面约每半秒更新；可点“原始大小”放大拼图，也可在网页取消登录。默认遮挡画面中的输入；需要本机调试时可在 `.env` 中设置 `AUTOSCOUT_SHOW_LOGIN_INPUT=true`。手机号和验证码只短暂放在服务器内存里交给浏览器，不写入程序日志或状态文件。登录后定时扫描复用保存的会话；若 SteamPy 浏览器配置跳回登录页，会先尝试恢复本机保存的有效会话快照。快照也失效时，回到 `/auth` 重新验证。不要上传会话目录或诊断截图。

`--remote-debug` 让服务监听服务器所有网卡。另一台设备访问 `http://服务器IP:8000/auth`，输入服务器启动时打印的访问密码；可通过 `.env` 的 `AUTOSCOUT_DEBUG_PASSWORD` 固定密码（至少 8 字符）。远程设备只能访问受密码保护的登录页面、启动登录、填写验证信息及操作拼图；扫描和资金台账仍限本机。若跨设备打不开，检查服务器防火墙和端口。页面使用普通 HTTP，跨不可信网络应通过 VPN 或 SSH 转发访问。调试完成后可去掉 `--remote-debug` 并重启服务。

命令行登录仍可作为备用方式：`python -m autoscout login sonkwo` 或 `python -m autoscout login steampy`；已有且尚未过期的短信可加 `--reuse-code`。要取消命令行登录，也可在网页点“取消登录”。

启动后默认先同步已有订单和钱包流水，再自动扫描，以后每 30 分钟更新。可在 `.env` 中调整 `AUTOSCOUT_SCAN_INTERVAL`、`AUTOSCOUT_SCAN_KEYWORDS`，或用 `AUTOSCOUT_AUTO_SCAN=false` 关闭自动启动。页面可暂停和恢复巡航，也可手动同步订单、提现流水、发起扫描、登记交易；命令行一次性同步与扫描：

```bash
python -m autoscout sync-orders
python -m autoscout sync-payouts
python -m autoscout scan --keyword "空洞骑士" --pages 1
```

已有订单统计从 2025 年 1 月 1 日 00:00（中国时间）起计算。2024 年及以前的购买和销售订单仍保存在本地原始记录中，但不进入统计、订单列表、进货表或买卖配对，也不为新销售分配成本。主表把每件杉果已完成购买商品单独列成一行；同一订单买入多件会显示多行，各自展示购买订单、单件成本、分配到的 SteamPy 普通或求购成功销售和价差。普通成交显示原价及订单费用；求购成交只显示可与 AK 钱包入账核对的扣费后收入，原价及费用留空，避免从字段差额臆测费用。未配对的买入成本单独列出，不直接算亏损。

杉果退款读取每条商品明细的 `subOrders[].status`。当前真实接口的 `0/1/2/3` 分别表示创建、完成、退款成功、退款申请中；也接受官网组件规范化后的对应字符串。只有 `2/refunded` 才剔除，`3/refunding` 尚未退款成功。状态缺失或未知时停止同步并保留旧快照，避免把不明状态计作进货。整单仍是 `completed` 时也会剔除其中已退款商品；同单其他商品保留。退款商品的原实付金额从净消费中扣除，其件数与成本不进入进货表或买卖配对，原始商品明细仍可在“已退款商品”和订单收支中查看。会话失效时，由用户核对确认的商品退款会保留确认依据和时间，后续同步不会把它重新计作进货；明细名称、数量或单价改变时停止覆盖并提示核查，平台退款记录确认后改用平台依据。

首页顶部集中显示杉果净消费（原实付减已退款商品原实付）、SteamPy 净收入（普通和求购成交已扣订单费）、提现扣款合计、提现手续费和已核对的银行到账。顶部金额统一从 2025 年起统计。未录入银行流水时显示“待核对”；录入或更正到账后立即更新。银行到账与提现扣款分别展示，不从平台扣款推断实际到账。

资金总览另列 SteamPy 钱包收支：销售入账减提现、提现费和其他支出，加其他入账，得到本期流水净变动。其他扣款、退款返还、充值或未知平台类型均保留明细及关联单号，不按类型名猜测用途，也不自动摊入进货成本。可用余额与待入账金额读取官方钱包余额接口，与完整历史流水在同一轮同步后保存；只有金额有限且读取成功才发布新快照。可用余额与全部已同步流水净额的差额单独显示，不当作利润或费用。2025 年前流水只用于解释余额，不计入本期收入；旧快照未读取官方余额时显示“未读取”，不会把流水净额当作已核实余额。销售订单还需逐笔核对钱包入账，合计相同不能代替单号与金额的核对。

SteamPy 成交导入覆盖卖家中心 CDK 的“普通订单总列表”、相应成功订单以及“求购订单总列表”。杉果和 SteamPy 分别完成全部分页校验后发布；一方读取失败时，若有该方上次完整快照，则保留其订单并继续更新另一方，同时保存来源警告和各来源的实际同步时间，服务重启后仍可见。两方都无法更新时不会把旧快照伪装成新数据。普通成功销售按订单号与 K 钱包入账核对，求购状态 20 的销售按订单号与 AK 钱包入账核对；求购成交使用完成更新时间而非买家发布求购的时间。缺失、金额不符、未关联的正向流水和其他非提现扣款会单独提示。挂单列表和库存总列表尚未参与逐件核对，因此“未找到对应成交”表示已同步成交中没有可对应的销售；上架和库存状态仍待确认。订单价差仍须核对提现与银行到账，也须归因其他钱包扣款，才能判断实际套现结果。

SteamPy 未作为有效成交的订单记录单独列出，保留平台原始状态码；同款商品之后若有其他订单号的成功销售，也会列出，但不将其认定为同一激活码或同一上架记录。“每笔订单收支”可按平台、状态、商品名或订单号筛选，商品名搜索覆盖整单中的每条购买明细及其官方别名。混合购买订单展示全部商品、各自件数与单件成本，整单总件数和整单支出另列；主进货表始终按每件商品列行，不将商品在订单中的序号显示为购买件数。

配对先比较完整商品名、官方中英文名、括号内双语名称、版本、DLC 副标题、购买时间与件数，再对已确认同款的历史订单按先购先销分配买入成本。名称仅有模糊相似度不会自动配对。已售订单价差是扣订单费用后的卖出收入减买入成本，尚未核对实际激活码、提现到账与相关费用，不能作为已实现利润。购买订单可能并非用于 SteamPy 出售，销售订单也可能来自其他进货渠道。程序只保存必要的订单与钱包流水元数据，不保存 CD Key 或完整平台响应。账号会话失效或同步失败时，会保留上次完整统计并显示错误。

SteamPy 提现表读取完整钱包历史，不受平台网页默认近一月日期范围限制。提现扣款、提现费用和银行到账分列；尚未录入真实银行流水时显示“待核对”。录入的到账金额属于手工核对记录，可更正或撤销；它没有与具体销售自动分摊，因此不会被计入逐单已实现利润。

杉果会话由受保护的账号接口核验，扫描、订单同步和网页登录检查共用同一套处理。当前访问令牌约一小时有效，过期前或收到 401 时自动调用官网 SDK 使用的续期接口，并验证、保存新会话；浏览器配置缺失时尝试恢复本机快照。续期凭证也被平台拒绝才要求短信登录。网络超时、服务器错误或接口格式变化会报告可重试的来源错误，保留会话和订单快照；不会据此宣称登录过期。会话快照原子替换，账号凭证不进入程序日志。

数据与轮换日志在 `AUTOSCOUT_DATA_DIR`，默认 `~/.autoscout/`。扫描结果保存在 `autoscout.sqlite3`。例如，跨语言商品名可在该目录创建 `aliases.json`：

```json
{
  "Hollow Knight": ["空洞骑士"]
}
```

别名代表你已人工确认它们指向同一游戏；系统仍独立核对版本和内容类型。修改后运行 `python -m autoscout reconcile-orders` 即可重新配对已保存的订单，不会访问账号或重新收取验证码；重启服务后新别名也会用于后续扫描。

## 验证与限制

### 买方需求与市场趋势

扫描分别保留挂价利润与求购价利润，均扣除卖出费用和提现分摊。只有同一 SteamPy 商品编号的国区有效求购报价在扣费后也达到门槛，才进入默认的“有求购的候选”；只有卖家挂价能达标的商品进入“仅有挂价差”。每款只估 1 件，不将求购条数直接乘成预计收入，也不承诺求购能即时兑现。旧扫描未采集需求的结果保留原价格、时间与金额，重新标为仅有挂价差。

需求来自官方公开 `wantKeyOrder/showGame` 列表，只接受详情编号和官方名称一致、未删除且 `txStatus=02` 的求购单。供给来自当前商品页实际请求的 `steamKeySale/listSale`，核对国区、人民币、价格升序、页码、总数与条数。每种列表最多读取 3 页；超出时库存显示为采样下限，求购条数显示“至少”，不会将不完整列表写成完整市场总库存。读取失败时需求显示未核实，不冒充零求购。

每次巡航保存公开价格、库存和求购的汇总快照，按商品编号、区域与商品信息指纹隔离。至少间隔 30 分钟才比较趋势，最多比较最近 7 天，优先选择距本轮约 24 小时的观察，并显示实际时间跨度。详情变化会开始新的观察序列。没有可信的此商品成交时间记录时，近 7/30 天销量与预计售出天数保持未知：卖家累计成功交易数、库存减少和求购撤单均不作为产品成交量。报价超过 5 分钟时页面提示重新扫描；页面刷新只读取本地记录，巡航默认每 30 分钟重新访问平台。

### 自己的成交证据与资金周转

`/api/account-orders/turnover` 与进货展板共用完整逐件台账，不受分页或页面筛选影响。从 2025 年起，排除退款件与失败销售，统计购入至已配对成交的持货时间、7/30 天内配对比例、仍未配对的件数/成本/持货年龄、逐款最近成交，以及最近 12 周自己已配对销售件数。历史按先购先销分配，资本持有天数不证明实际激活码身份或连续上架时间。

7/30 天内配对的分母只包含在共同观察截止时间已购满该天数的整批进货，包含未配对的件。观察时间不足的购买整件排除，即使已快速卖出也不会提早混入分子。共同观察截止采用杉果、普通销售、求购销售同步时间的最早值；部分来源过期不会凭最新页面刷新时间延长旧样本的观察。未覆盖求购时不显示完整成交比例；仍有成功销售未配对时明确说明比例是已确认的下限。

SteamPy 订单 `createTime` 是买方下单时间，不能用于估计上架等待时间。只有成功订单嵌入的 `steamKeySaleDetail.createTime` 可计算对应平台库存记录创建至成交的时间，页面单独标注它也包含上架前或暂停时间，缺失或无效时保留未知。求购成交按已核验的完成时间统计，不猜测平台没有提供的库存创建时间。

候选只关联商品编号与完整官方名称/版本一致的个人历史；同一 AppID、相似名字或相异 SteamPy 商品编号不会混用。个人近 7/30 天销售单列为自己的样本，全市场销量仍保留未知。近 30 天至少 3 件具有独立成交原价的普通销售时，可展示价格下四分位和按当前成本/费率重算的情景利润。求购净收入不冒充普通成交原价，历史价格情景不会自动升级为可立即兑现的候选。

运行离线测试：`python -m pip install -e '.[test]'`，然后 `python -m pytest -q`。测试覆盖价格歧义、跨语言别名、版本冲突、费用计算、扫描去重、资金到账与 API 操作权限。

杉果商品与订单、SteamPy 市场报价与卖家订单均已用已登录账号实际读取验证。真实资金动作仍需要订单配对和到账凭据。若会话过期或页面结构变化，同步或扫描会报错，保留上次完整订单统计；此系统不提供收益保证。
